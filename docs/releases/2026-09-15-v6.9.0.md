# Livingware Engineer 6.9.0

**Release date:** 2026-09-15

Livingware Engineer 6.9.0 refactors the skill system around explicit runtime ownership and adds bounded process-style counterfactual evaluation.

## Layered skill runtime

Skills are now treated as discoverable workflow-entry packages rather than the owner of every rule. The canonical split is:

- **Tool / Operator** — invariant executable mechanics and deterministic regression tests.
- **Policy / Invariant** — stable cross-cutting non-executable constraints.
- **Workflow** — reusable state transitions, recovery, and handoff structure.
- **Router** — recurrent current-state choice after meaningful observations.
- **Skill** — compact discovery/entry surface with progressive-disclosure pointers.

Failure/change authority follows attribution: implementation and environment defects remain local, capability defects go to tool owners, and steering defects are attributed to routing, workflow, or policy before shared learning is proposed.

## Counterfactual / what-if evaluation

Adds `scripts/simulate-workflow-counterfactual.py`, a Python-standard-library evaluator supporting:

- deterministic `REPLAY`;
- seeded finite-state `MONTE_CARLO` what-if simulation;
- an explicit boundary to real `REAL_REEXECUTION` rather than faking real execution.

Evidence provenance remains mechanically distinct as `OBSERVED | REPLAYED | SIMULATED | INFERRED | ASSUMED`. Simulation may rank, falsify, or narrow candidate changes, but cannot manufacture materially independent empirical evidence or claim identified causal effects.

## Workflow refactors

- `systematic-debugging` now keeps activation/invariants in the root while recurrent debugging topology lives in `references/workflow-routing.md`; deterministic helpers remain operator-owned.
- `executing-plans` now owns plan continuity and authorization boundaries while dynamic execution topology lives in `references/workflow-routing.md`; debugging, TDD, and completion verification remain separate current-state owners.
- `writing-skills` and `skill-review` now enforce layer ownership and route detailed evaluation/learning rules to canonical references.
- Existing TDD, verification, and compatibility routing skills were retained where the new audit found no concrete ownership defect.

## Routing and token economics

The live Codex probe now separates routing evidence, behavioral outcome, runtime status, forbidden-neighbor activation, and token usage instead of collapsing them into one pass/fail result. The 2026-09-14 authenticated live benchmark remains the historical performance baseline; this release does not claim a new live token/latency improvement without a fresh authenticated run.

## Packaging and release integrity

- Codex manifest explicitly uses `"hooks": {}` to suppress accidental SessionStart fallback discovery.
- Marketplace and package tests now use the Livingware Engineer identity rather than stale upstream `superpowers` assertions.
- `.version-bump.json` was repaired to match `scripts/bump-version.sh`, includes itself as a synchronized version surface, and is checked in CI.
- All declared package/plugin manifests are synchronized to `6.9.0`.

## Verification

The release commit is covered by the `Layered Runtime Verification` workflow. The gate verifies:

- version-manifest consistency;
- progressive skill loading;
- layered skill/token-economics contracts;
- systematic-debugging operator behavior;
- counterfactual evaluator behavior and provenance boundaries;
- Codex marketplace manifest correctness;
- deterministic Codex package archives.

Detailed implementation and acceptance evidence is recorded in `docs/benchmarks/2026-09-15-layered-runtime-counterfactual-eval-acceptance.md`.
