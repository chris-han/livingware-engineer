# Livingware Engineer 6.9.1

This release combines the IA-before-UI design workflow with Verification Impact Analysis.

## IA before UI

Material user-facing structure changes now require a bounded information-architecture review before production UI coding. The gate checks user task/domain model, semantic ownership, placement hierarchy, Fast-to-Aha flow, state/recovery ownership, interaction semantics, responsive composition, shared-pattern reuse, and evaluability. It is an engineering-process gate, not a blanket human-approval checkpoint.

## Verification Impact Analysis v1

Verification scope is selected from observed production impact radius rather than diff size or fixed CI habit. Existing R0-R3 impact-radius testing is now named and documented as Verification Impact Analysis v1, with codebase-memory/code-graph evidence preferred when it materially improves confidence.

The release also restores a three-cadence verification model:

- D0 deterministic invariants
- D1 local semantic sentinels
- D2 full semantic audits

Broad CI is reserved for genuinely broad/high-risk/uncertain or release-level changes rather than automatically following every local implementation step.

## Combined workflow

```text
requirement / problem
  -> architecture + semantic-owner impact
  -> IA-before-UI when applicable
  -> implementation plan
  -> focused TDD
  -> Verification Impact Analysis
  -> smallest sufficient integration/browser/E2E evidence
  -> completion / MVL evaluation
```

IA-before-UI determines whether the intended user-facing structure is conceptually correct. VIA determines how much implementation evidence that change needs. MVL evaluation remains separate and measures whether the feature produced intended value and learning.
