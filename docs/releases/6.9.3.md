# Livingware Engineer 6.9.3

This release makes the planner compose IA-before-UI and Verification Impact Analysis as one explicit engineering workflow.

## Combined planning contract

Material user-facing IA changes now require an `IA-Before-UI Review` before production UI implementation. The planner records applicability, user task/domain objects, semantic ownership, region hierarchy, Fast-to-Aha path, state/recovery ownership, reuse, responsive constraints, verification evidence, stop-condition status, and `GO_FOR_UI | REVISE_IA | NOT_APPLICABLE` disposition.

After the implementation surface is known, Verification Impact Analysis selects the smallest sufficient test surface from R0-R3 and records uncertainty, selected tests, and intentionally omitted broad suites. D0 deterministic invariants, D1 local semantic sentinels, and D2 broad semantic audits remain separate cadences.

The resulting sequence is:

```text
requirement / MVL hypothesis
  -> IA-before-UI when applicable
  -> implementation
  -> focused TDD
  -> Verification Impact Analysis
  -> smallest sufficient integration/browser/E2E evidence
  -> MVL measurement and re-test
```

## Acceptance additions
