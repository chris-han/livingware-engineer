# IA / UX review checklist — 可执行检查清单

本清单用于 [设计原则](ia-ux-principles.md) 的结构评审与实施验收，沿用 `docs/ia-before-ui.md` 的唯一 gate。按变化的影响范围选择适用项；已有证据可以引用，不必为每次小修复填写整表。不要把清单变成新增审批、遥测数据库或重复验收文档。

## 使用与证据

每个适用项记录 `PASS | FAIL | UNVERIFIED | NOT_APPLICABLE`，附现有 spec、源文件、测试或观察位置；`NOT_APPLICABLE` 说明理由，缺证据不得写 PASS。证据类型为 **I**（IA/契约检查）、**D**（确定性状态/数据验证）、**B**（真实浏览器任务与呈现）、**H**（真实人类任务研究）。I/D/B 不能替代 H；H 也不代替数据完整性与权限验证。

只对适用的工程缺陷执行现有 `REVISE_IA`：错误归属、相互竞争的所有者、缺少必要前提/恢复、隐藏重大后果、不可达的关键动作等。人类收益未测量本身不新增工程阻塞；若用户或现有验收契约明确要求该收益，则相应收益/完整任务完成声明须保持未证明，不能用清单缩小原合同。

## 按场景选择最小证据

| 场景 | 重点项与反例 | 验证目的 |
| --- | --- | --- |
| 首次进入任务 | C03–C04、C09、C11；从无关全局上下文进入 | 范围正确且第一项有用操作可发现 |
| 恢复会话 | C06、C10、C25；材料版本变更或未完成处理后重开 | 恢复实际状态并标记过期，避免重复输入 |
| 切换与竞态 | C23–C24；旧工作区请求在新工作区请求后完成 | 所有消费者及导出不串任务 |
| 复核与未知 | C15–C17、C28–C31；缺原文、矛盾或不完整材料 | 用户可校核依据，未知不被伪装成确定 |
| 窄屏与键盘 | C19、C32–C35；长标签、短高度、抽屉开闭 | 同样范围和判断信息可达，焦点/滚动可恢复 |
| 人类收益 | C38–C40；合理比较成功/错误/恢复表现 | 支持具体收益；不能由 AI 模拟或 E2E 代替 |

这些是按影响选择的场景，不要求每次修复运行全产品矩阵。优先复用当前有效证据；新增检查必须能检测本次引入的失败。QuickE2E 或 AI walkthrough 可作探索线索，所需的确定性 replay 和浏览器呈现证据沿用现行契约。

## 人类任务研究的最小记录

只有当收益声明需要 H 时，先在原有任务/研究契约中说明研究问题、用户群与熟练程度、可比基线/候选、材料和顺序、主要质量/效率指标、预算与结论范围。保留失败与未完成任务，必要时控制顺序/学习效应；不能因为任务更快就忽略错误增加。自报告努力与完成时长是不同证据，只有测量设计支持时才声明认知负荷减少。不得规定脱离任务的统一百分比改善门槛。

清单和人工评审可以完成规范维护，但不能建立广泛的代理行为提升或人类收益结论。是否开展行为学习/人类实验仍由原有授权与研究流程决定。
