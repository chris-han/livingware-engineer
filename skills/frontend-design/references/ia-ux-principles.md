# IA / UX design principles — 信息架构与认知工作分配

用于任务上下文、材料准备、跨面板交互、信息层级、渐进披露或恢复路径发生变化的设计与评审。先应用现有 `docs/ia-before-ui.md`；本参考补充其推理与检查方法，不建立第二个 IA gate、产品语义权威或审批流程。一般原则适用于不同产品；后文 Semantier 示例仅在项目现行设计与运行时契约支持时采用。

## 证据与规则的关系

[研究依据](ia-ux-evidence.md)记录原始来源 S1–S6、阅读范围、支持的前提与限制。[检查清单](ia-ux-checklist.md)将下列原则转成可观察条件。原则是 Livingware 对这些前提与现有工程约束的设计综合，不是原著逐条给出的产品标准，也不是已经测得的认知负荷改善。

核心目标是把用户的注意力用于必要判断，让系统承担可可靠完成的记忆、定位、对齐、计算与恢复。自动化、省点击、信息少、任务快是不同性质的指标；任何一个都不能单独证明理解、判断质量或整体可用性改善。沿用 Fast-to-Aha 与 Fix → Infer → Recommend → Ask，保留原有授权与执行边界。

## 设计原则 P01–P16

### P01 — 从任务结果与领域对象建立 IA（Job and domain model）

先说明谁在什么情境下，要对什么对象取得什么进展，以及怎样判断成功，再选择布局与控件。把系统内部过程映射成用户可理解的任务概念；“生成图谱”可作为实现手段，不能替代“核对岗位要求”这样的目标。检查每个控件是否服务于当前任务、必要领域对象或确有用途的系统操作。**依据：S1、S2；具体任务分解属于项目设计。**

### P02 — 先呈现作用范围，再呈现范围内动作（Context before action）

把工作区、任务、对象与视图分清，先解析会决定归属或行为的上下文，再允许依赖它的上传、编辑或执行。自动推断只免除选择操作，不免除显示当前作用范围：用户仍应能识别操作属于哪里。视觉和 DOM 阅读顺序应表达同一依赖；键盘用户到达动作时应能取得相同上下文，不把静态标题强行变成可聚焦控件。**依据：S1–S3；上下文前置是综合推论，header 位置是项目选择。**

### P03 — 每个状态只有一个语义所有者（One owner, coherent projections）

保留一个状态所有者与规范的变更契约，允许多个区域显示一致的只读线索；确有任务用途的多个操作入口必须调用同一契约，不能成为竞争性所有者。Header、材料列表、中心区域、Inspector 与 chat 必须引用一致的任务和对象依据，不能各自持有可竞争的业务状态。切换上下文时，清楚表达正在切换，防止旧请求把结果写回新上下文；正确性可以通过协调更新或明确的过渡状态实现，不规定必须使用某种技术架构。**依据：S4 支持整体分析；单一所有者来自现有工程规则。**

### P04 — 按信息依赖披露进展，保留复核与修订（Dependency-aware progress）

区分输入、由输入形成的判断依据、处理结果和可复用的既有依据。后续动作的出现与可执行性依据真实前提，任务状态依据真实产物；不要把尚未生成的输出伪装成前置配置。依赖顺序不等于单向向导：用户可以回看原文、修订材料、复用已有依据并比较多个候选结果。对象生命周期与用户任务进展分别命名。**依据：S2、S3、S6；具体依赖由产品契约确定。**

### P05 — 把恢复任务所需的信息留在界面上（Recognition and external memory）

显示材料角色、当前选择、已完成工作、待核对项与下一步，使用户无需回忆进入路径或重复输入。状态保留到原有任务/会话所有者，重开时恢复可验证的工作位置，并标明材料或依据变化造成的过期；不要为“帮助记忆”另建一套持久化状态库。区分真实材料、示例和未采用的模板，避免熟悉的文件名造成错误识别。**依据：S1、S4、S5。**

### P06 — 用排列与对齐承担比较工作（Spatial computation）

用相邻、分组、统一字段与对齐关系表达用户需要比较的差异。涉及判断时，在相同基准下联结要求、候选人证据、原文和缺口，让用户辨别匹配依据而非记住数值后跨面板对账。图谱、卡片和表格按任务选择；不能要求用户从复杂拓扑中自行推导可直接显示的判断关系，也不能用布局暗示未经验证的因果关系。**依据：S3、S4；具体比较表是设计推论。**

#### P06 应用契约 — 联动证据与连续阅读（Linked evidence and continuous reading）

当任务需要关联总体结果、判断/过程和具体证据时，沿用 P03 的单一状态所有者，按以下契约设计；详细要求属于现有 P06/P05/P10/P14/P15 的应用，不增加新 gate、统一数据平台或固定三栏模板。它是本次明确产品需求与既有原则的设计综合，未宣称新增外部研究结论或测得的人类收益。

1. **先定义关系，再排面板。** 在现有 IA 记录中写明用户要核对的问题、对象与版本、关系类型、证据出现位置、现有所有者、双向入口和返回路径。只显示所有者能提供的引用、支持、反证、适用、推导、执行或修订关系；引用不等于支持，共用来源不等于父子谱系，修订不等于改进。推断的关联须显式区分，不能伪装成精确绑定。
2. **允许从任一相关对象进入。** 从概览定位具体判断/过程及证据；从证据反向列出关联判断。保留一个焦点对象和带关系标签的关联集合，使用已有选择契约，不建立面板各自的业务选择。一对多/多对多需显示可读列表、范围内数量和明确的下次选择，不能静默选第一条；反向索引不可用不等于没有关联。
3. **分开 hover、选择、导航与业务动作。** Hover 仅作瞬时预览，不提交选择、切文档或写历史。明确选择才联动相关表示；导航/高亮不得隐式接受结论、修改规则、生成事实标签、训练信号或激活授权。异步完成不夺焦点、不自动打开抽屉。
4. **保留阅读上下文与返回。** 通过现有 route/session 所有者传递作用范围、对象/版本、来源/出现位置、视图/过滤器及返回点。显式定位允许滚动相关证据区，并提供返回和合理焦点恢复；后台刷新不得重置阅读位置。只承诺已有持久化支持的重开恢复；版本失效时解释变化，不静默改绑最新版。
5. **精确身份与呈现精度分别表达。** 使用来源所有者提供的稳定定位，不靠相同文字、文件名、颜色、邻接或 DOM ID 认定关系。精确绑定但降级呈现时标明精度；重复文字歧义、失效锚点或版本不符时不画假精确高亮。保留上下文和可恢复操作，不让证据不可达清空整个任务。未加载、拒绝、未知、已知为空、过期和渲染失败不得混同。
6. **保持同一依据并隔离竞态。** 明确各表示的作用范围和当前版本；旧 A 请求不能覆盖新 B 选择。局部加载可保留，但须显式显示过渡，避免旧高亮看似属于新判断。选择变化不得无谓重新加载未变化的来源；联动不等于让不同来源强制同步滚动位置。
7. **保持判断和访问能力。** 重大例外、反证、不确定性及适用范围就地可见；关系类别、已选对象和定位状态不能只靠颜色。窄屏通过命名视图/已有抽屉保留同一身份、关系和返回，键盘拥有等价路径；不强制三面板同时可见或第二 Inspector。
8. **验证双向闭环与失败恢复。** 按影响检查总体结果→判断/过程→精确证据→返回，以及证据→关联判断；加入重复段落、多来源/多父节点、反证、版本替换、快速 A→B 与逆序响应、来源不可达、窄屏和键盘路径。身份/状态检查与真实渲染精度分别验证；文档规则不构成产品实现、行为提升或人类认知收益证据。

**通用迁移：** 审核场景可关联材料、判定与规范依据；评测场景可关联运行对比、任务/修订轨迹与输入/产出/评审依据。实时执行、历史回放和模拟须可辨。具体领域关系、权限、完整性及状态枚举始终来自项目契约；本参考只规定 IA 推理和呈现义务。

### P07 — 动作之前说明对象、结果和后果（Feedforward and mapping）

让按钮名称、邻近对象和说明共同表达“对谁做什么、会得到什么、影响什么”。区分切换/选择、保存/修改、生成/执行及授权/激活；只有确有区别时才分成多个动作。图标、颜色或空间位置不能成为理解重大后果的唯一渠道；禁用动作须提供前提缺口与可行解决入口。**依据：S1、S2；权限差异由运行时所有者决定。**

### P08 — 反馈说明实际状态变化（Meaningful feedback）

分别表达输入已接收、处理中、局部完成、失败与最终结果，告诉用户哪些内容改变、哪些尚未确定、下一步能做什么。长任务允许离开并在返回时检查进展；进度百分比必须有真实计算依据，无依据时使用阶段状态。不要用“状态已更新”替代结果，也不要频繁通知无须用户关注的后台细节。**依据：S1、S2。**

### P09 — 披露次要细节，同时保留必要背景（Progressive disclosure）

先呈现完成当前判断所需的背景、证据摘要与可行动信息，将低频参数、技术元数据和深入说明按需展开。把按重要性隐藏细节的渐进披露，与按任务前提推进的分阶段披露分开设计；必要的不确定性、重大后果、材料归属与证据缺口不能藏在“高级”面板。折叠应可发现、可恢复，也要提供上下文内的简短帮助。**依据：S1、S6；风险与证据要求来自项目契约。**

### P10 — 动态变化保留位置、焦点与可解释性（Stable adaptation）

根据任务状态、选中对象和实际材料调整内容，但保留稳定的区域职责、选中项、焦点和合理的滚动位置。用户阅读或操作期间避免无提示重排；异步完成不能强行夺走焦点、打开 chat 或滚动到新卡片。直接请求下一步可采用有理由的导航，并提供返回；动态更新须让键盘和辅助技术用户同样理解变化。**依据：S3、S4 支持任务环境协调；这些交互约束是工程综合。**

### P11 — 预防可避免的错误，解释可修复的缺口（Prevention and diagnosis）

从真实易错点设计：错工作区、错材料角色、重复提交、版本过期、缺前提或输入格式不兼容。可确定且无损的格式处理由系统完成，同时保留原始材料及重要转换痕迹；有歧义的内容不能静默改写。错误说明发生了什么、影响范围、已保留什么和如何恢复，不让用户解释内部异常码。**依据：S1、S2。**

### P12 — 把中断、失败和重开纳入主路径（Recovery by design）

在失败、取消、断连、重开和切换对象时保留可安全复用的材料与工作位置；报告未保存、未完成或过期的内容。恢复操作指向既有状态所有者；在可能重复外部效果时遵守已有幂等/执行契约，不假装每个动作都能安全重试。返回应恢复复核上下文，而非让用户从首页重新拼装依据。**依据：S1、S2、S4、S5。**

### P13 — 保留用户控制与熟练路径（Control, flexibility and contextual help）

提供取消、返回、适用的撤销以及可查的操作后果；不可逆动作不能承诺不存在的撤销。自动默认值应可识别并在授权内调整。新手使用清晰示例与就地帮助，熟练用户可复用输入、批量处理或使用快捷操作，不为两类用户创造互不一致的业务流程。重大变更按现行契约介入，普通可逆路径不增加形式化确认。**依据：S1、S2；介入规则沿用 MVL Law 1。**

### P14 — 卸载执行负担，同时保持判断可校核（Calibrated assistance）

系统可以定位、计算、比较和推荐，但应让用户看见所用依据、范围与未解决项。原文、推断、候选结论和已确认结果分别标识；未校准的模型分数不能包装成正确概率。使用户能检查、纠正或保留未知，且不要把点击反馈自动变成事实标签、学习信号或激活授权。**依据：S5 支持卸载有代价；这些语义/学习边界来自项目运行时。**

### P15 — 在不同访问方式下保留语义层级（Accessible hierarchy）

窄屏、短屏、中文/英文、长标识、键盘和辅助技术下，仍能识别作用范围、状态与主要动作。区域可以折叠或移入抽屉，但其名称、关系、到达路径与焦点返回必须明确，不能以截断隐藏唯一的辨别信息。保持可读密度与清楚层级，状态不能仅靠颜色；按项目适用的可访问性规范验证，不用本清单代替该规范。**依据：S1–S3 的可理解性前提；具体访问要求是工程要求。**

### P16 — 把结构正确、任务表现与认知收益分开证明（Evidence-calibrated usability）

设计评审可提出预期收益，浏览器与确定性检查可证明任务路径和状态一致，人类参与的任务研究才支持其范围内的可用性或负荷结论。预先选与任务相关的成功率、错误率、恢复成本或查找表现；注意速度与判断质量的权衡。点击数、AI walkthrough 和漂亮截图均不能独立证明认知负荷减少。缺少测量时写明未测量，不能编造基线或阈值。**依据：S1、S3、S5 的研究边界与现有证据规则。**

## Semantier 工作台应用

以下是本次用户明确要求的设计指导，尚不表示当前运行代码已经实现或验收。Semantier 的当前 `docs/operational/design.md` 与实际应用源文件拥有 UI 约束，运行时契约拥有任务、权限与依据语义；本例不能替代它们。按 [Asimov alignment](asimov-alignment.md) 定位现行模板、样式与组件。

| 上下文层级 | 回答的问题 | 推荐角色与所有者 |
| --- | --- | --- |
| 全局/租户 | 我以什么身份、在哪个组织操作？ | 保留现有应用级身份所有者，不把它与工作区混成一个选择 |
| 工作区 | 后续材料和操作归属于哪里？ | 持续可见的 header 上下文；在该工作台中作为唯一工作区切换入口 |
| 任务/会话 | 我正在处理哪件工作？ | 当前岗位或案件、任务进展与下一步；使用真实任务/会话所有者 |
| 材料/依据 | 当前判断基于什么？ | 材料区显示角色、来源、状态；要求与证据区显示形成或复用的依据 |
| 选中对象 | 我正在检查哪项内容？ | 中心选中项驱动 Inspector 与 chat；辅助面板显示自己的明确对象范围 |
| 视图/表示 | 我怎样查看同一对象？ | 搜索、过滤、展开、图谱视图属于表示，不自动修改业务事实 |

从 `taskIntent=resume-screening` 进入时，先解析/恢复真实任务上下文，再显示“当前工作区：简历筛选”与当前岗位，随后呈现 JD 和简历输入。若入口只表达任务意图而不能唯一确定实际工作区，不据名称创建或猜测归属；沿用现有解析规则，必要时才让用户消解冲突。Header 的领域名称与真实绑定必须一致，不能仅换一个标题。

材料区下方不再保留竞争性的工作区选择。多个只读上下文提示可保留，但不能形成第二切换入口。“岗位要求候选图谱”若由 JD 产生，放在 JD 准备之后；若复用已有岗位要求，提供显式复用分支；若只是保存目标，采用可见默认值与次级修改入口。这三种语义须由现有代码/契约确认，不能从截图下结论。

把任务进展表达为真实材料准备、岗位要求形成/核对、筛选与证据复核状态，允许回看与修订。`lifecycle=DESIGN` 若是图谱生命周期，应以“图谱阶段”表达，不冒充筛选任务进度。示例 JD 提供“使用示例 JD”的明确动作，采用前标明示例，采用后显示实际材料状态；禁止沿用无关 POC 文件。自动引导优先让入口在初始布局中可见，用户主动请求引导时才有控制地定位并支持返回，不靠异步自动滚动弥补错误层级。

切换工作区、任务、JD 或候选人时，核对 Header、材料归属、中心依据、Inspector、chat 与导出对象的真实关联。旧响应只能归入原上下文或被拒绝，不能混入新对象；任务相同也不等于材料版本相同。保留 UNKNOWN 与待核对事实，既有 assessment、admission、activation 边界不因 UI 简化而改变。

## 执行与验证

在现有设计/计划中记录受影响原则 ID、当前缺陷、最小变化、所需状态与证据；只使用 [检查清单](ia-ux-checklist.md) 的适用项，不建独立状态台账。设计分歧按项目所有者解决；一般改善可以自主推进。按现有 IA gate 给出 `GO_FOR_UI`、`REVISE_IA` 或有理由的 `NOT_APPLICABLE`，再按现有 VIA 选择足以证伪本次变化的验证范围。

对于这个工作台的上下文调整，核心场景是首次进入、重开恢复、上下文冲突、切换时旧请求返回，以及桌面/窄屏/键盘下的完整复核路径。它们验证结构与实现；人类完成相同任务的比较才支持相应可用性收益。本次规范发布不直接修改 Semantier UI，也不自动启动人类研究或行为学习实验。
